# 난장판 코믹 레이싱 게임: 개발 설계 문서

> Claude Code에게 넘기는 문서입니다. Roblox Studio + Luau 프로젝트입니다.
> 게임 이름과 수익 모델은 아직 미정입니다.

---

## 0. Claude Code 작업 규칙 (먼저 읽기)

1. **애매하면 추측하지 말고 질문하기.** 이 문서에서 정하지 않은 수치, 규칙, 동작은 임의로 정하지 말고 개발자에게 먼저 물어본다. 질문할 때는 선택지 2~3개와 추천안을 같이 제시한다.
2. **문서 내용에 문제가 있으면 태클 걸기.** 기술적으로 어렵거나, 성능 문제가 생기거나, 규칙끼리 충돌하거나, 게임성이 나빠 보이면 구현 전에 말한다.
3. **확장성 우선.** 차, 튜닝, 코스, 타이어는 앞으로 계속 늘어난다. 새 항목 추가가 "설정 데이터에 한 줄 추가 + 모델 하나 넣기"로 끝나야 한다. 코드 안에 특정 차 이름이나 코스 이름을 하드코딩하지 않는다.
4. **기존 코드 보존.** 요청하지 않은 기능이나 코드를 임의로 삭제하거나 바꾸지 않는다. 수정 전에는 변경 계획과 영향받는 기능을 설명한다.
5. **존재하지 않는 에셋 ID나 API를 지어내지 않는다.** 에셋이 필요하면 자리표시(placeholder)로 두고 목록으로 알려 준다.
6. **테스트하지 않은 코드를 테스트 완료라고 말하지 않는다.** 작업 후 변경 파일, 수정 이유, Studio에서의 테스트 방법을 알려 준다.
7. **설명은 한국어로, 어려운 용어는 쉽게 풀어서.**
8. 위험한 파일 삭제나 대규모 구조 변경 전에는 확인을 받는다.

## 1. 게임 한 줄 요약

웃기고 정신없는 **물리 기반 코믹 레이싱**. 큰 오픈월드를 이상한 탈것으로 친구 태우고 돌아다니다가, **5분마다 열리는 레이스**에 참여해 최대 8명이 경쟁한다. 아이템은 없고, 차이는 **차 몸통 + 오래 키운 튜닝**에서 난다. 세게 박거나 높은 데서 떨어지면 HP가 깎이고, 0이 되면 **엄청 크게 폭발**한다.

### 핵심 재미
- 웃긴 탈것 + 진짜 물리 + 래그돌(흐물흐물 날아가는 캐릭터) + 대폭발
- 친구 동승 + 동승자가 운전자 머리 때리기
- 튜닝 노가다로 차를 키우는 성장 재미 (튜닝 좋아하는 유저 타겟)
- 코스별 기록 경쟁

## 2. 확정된 설계

### 2-1. 물리 방식
- **진짜 물리 기반 + 아케이드 보정.** 물리로 굴러가지만, 조작감을 위해 어느 정도 잡아 준다 (예: 과도한 뒤집힘 완화, 공중 자세 살짝 보정, 드리프트 보조).
- 보정을 어디까지 할지는 구현하면서 개발자와 조율한다.

### 2-2. 조작 (PC 기준)
| 키 | 기능 |
|---|---|
| W / S | 가속 / 감속 + 후진 |
| A / D | 방향 |
| Space | 드리프트 |
| Shift | 부스터(니트로) |
| F | 차에서 내리기 (레이스 중엔 막힘) |
| L | 헤드라이트 켜기/끄기 |
| C | 시점 전환: 3인칭 ↔ 리얼 1인칭(운전석) |
| 마우스 클릭 (동승자) | 운전자 머리 때리기 |

- **점프 키 없음.** 점프는 점프대를 통해서만.
- 키 설정은 한 곳(설정 모듈)에서 관리해서 나중에 바꾸기 쉽게.

### 2-3. 차량 HP & 폭발
- 모든 차에 HP가 있다.
- **데미지**: 벽 등에 세게 부딪히거나, 점프대 후 높은 데서 떨어질 때. 충격 세기에 비례.
- **회복**: 일정 시간 데미지를 안 받으면 자동 회복. 데미지를 받으면 **3초 동안 회복 멈춤** 후 다시 회복.
- **HP 0 → 대폭발**: 운전자와 동승자 모두 래그돌로 크게 날아감.
- **오픈월드 폭발 후**: (미정, 7장 참고)
- **레이스 중 폭발 후**: 마지막 체크포인트에서 부활 + **2~3초 고스트 모드**.

### 2-4. 부스터(니트로)
- 시간이 지나면 자동으로 충전.
- Shift로 사용.
- 튜닝으로 **지속 시간(+충전 속도)**과 **출력(속도)**을 따로 강화.

### 2-5. 동승
- 친구를 태울 수 있다. 좌석 수는 차마다 다름.
- **동승자는 운전자 머리 때리기만 가능.**
  - 맞으면 운전자 화면 흔들림 + 짧은 시간 핸들이 랜덤으로 꺾임 + 효과음, 머리 젖혀지는 모션.
  - 쿨타임 있음 (연타로 운전 불가능하게 만드는 것 방지).
- **레이스에도 동승한 채로 참여 가능.** 레이스 도중엔 내릴 수 없음.

### 2-6. 시점
- 기본 3인칭 추적 카메라.
- C로 1인칭 운전석 시점 전환.

## 3. 차량 시스템

### 3-1. 차 몸통 원칙
- **비쌀수록 대체로 기본 성능이 좋다.** 하지만 차끼리 차이는 크지 않다.
- **가격 역전 이변 허용**: 싼 차가 속도는 비슷하거나 살짝 느린 대신 핸들링이 좋아서, 특정 코스에서 비싼 차를 이길 수 있다.
- 진짜 성능 차이는 **튜닝**에서 난다.
- 튜닝은 **차마다 따로 저장**된다. 새 차를 사면 튜닝을 처음부터 키워야 한다.

### 3-2. 차 목록 (초안, 계속 추가 예정)
| 차 | 컨셉 / 웃음 포인트 |
|---|---|
| 마트 카트 | 기본 차, 초보용 |
| 로켓 변기 | 빠름 |
| 가죽 소파 | 안정적 |
| 사무실 의자 | 핸들링 좋음, 제자리 회전 느낌 |
| 미니 피아노 | 출발이 빠름 |
| 관광버스 | 8인승 동승 특화 |
| 주전자 자동차 | 부스터 쓰면 주둥이에서 "삐이이" 소리 + 증기 |
| 하이퍼카 | 고급 스포츠카 포지션, 최고가 |
| 하이퍼가미 카 | 넓적한 종이판에 하이퍼가미 차트 그림, 밑에 바퀴 대충 꽂음. 초경량이라 점프대에서 제일 멀리 날아가고 공중에서 팔랑거림. HP 최하 |
| 침대 | 누워서 운전 |
| 냉장고 | 튼튼함. 폭발하면 음식이 사방으로 |
| 욕조 | 물 찰랑거림 |
| 2단 쇼핑카트 | 4인 동승, 사람이 위아래로 쌓임 |
| 잔디깎이 | 핸들링 |
| 아이스크림 트럭 | 6인 동승, 경적이 아이스크림 노래 |
| 거대 스케이트보드 | 드리프트 각도가 큼 |
| 관(棺) | 빠름 (할로윈 이벤트용으로도) |
| 자판기 | 튼튼함, 박을 때 캔 떨어짐 |
| 포크레인 | 느리지만 장애물에 강함 |
| 피자 배달 오토바이 | 1인승 |
| 의자 달린 로켓 | 직선 극속도, 핸들링 거의 없음 |
| 거대 고무오리 | 경적이 "꽥" |
| 바퀴의자 + 소화기 | 소화기 뿜으며 부스터 |

> ⚠️ **하이퍼가미 카 메모**: 차트 그림 데칼이 Roblox 에셋 심사에서 거부되거나 신고될 가능성이 있음. 개발자는 그대로 쓰기로 결정함. 거부되면 대체 그림으로 교체할 수 있게 **데칼을 차 모델과 분리된 교체 가능한 텍스처**로 만든다.

> 각 차의 정확한 수치(가격, 기본 속도, 핸들링, HP, 무게, 좌석 수)는 **미정**. 데이터 구조만 먼저 만들고 수치는 개발자에게 물어보거나 임시값으로 두고 표시한다.

### 3-3. 튜닝
**튜닝은 대가(단점) 없이 올리면 좋아지는 방식.** 대신 레벨이 높아질수록 비용이 크게 늘어서 **오래 플레이해야** 다 올릴 수 있다.

| 튜닝 | 효과 | 방식 |
|---|---|---|
| 서스펜션 | 충격 흡수, 출렁임 | 레벨 |
| 차고 | 차체 높이 | 슬라이더 |
| 캠버 | 바퀴가 안쪽/바깥쪽으로 기운 각도 | 슬라이더 |
| 오프셋 | 바퀴가 차체 밖으로 튀어나온 정도 | 슬라이더 |
| 엔진 | 최고 속도와 힘 | 레벨 |
| 엑셀 (흡기 방식) | 초반 가속 + 기어 올라가는 속도 | 레벨 |
| 브레이크 | 멈추는 힘 | 레벨 |
| 타이어 | 종류 선택 + 접지력 | 종류 해금 + 레벨 |
| 니트로 지속 | 부스터 지속 시간 + 충전 속도 | 레벨 |
| 니트로 출력 | 부스터 속도 | 레벨 |

**타이어 종류**: 슬릭 / 오프로드 / 레이싱 (3종)
- 지형별 접지력 차이를 줄지, 단순 성능 차이만 줄지는 **미정**. (설산과 화산 같은 거친 지형은 오프로드가 담당하는 방향으로 이야기됨)

**슬라이더(차고, 캠버, 오프셋)**: 주로 보이는 멋 + 약간의 주행감. 성능에 얼마나 영향을 줄지는 **미정**.

**제외된 것**: 구동 방식(RWD/FWD/AWD), 별도 변속기 튜닝, 점프.

**추가 아이디어 (개발자 확정 아님, 제안 단계)**
- 차마다 튜닝 세팅 저장 슬롯 여러 개
- 오픈월드 튜닝 시험장

## 4. 맵 (오픈월드)

### 4-1. 전체 구조
큰 오픈월드 하나. 레이스 코스는 **오픈월드 안의 구간을 잘라서** 만든다 (맵을 따로 만들지 않음).

```
        [설산 정상]
            ↓
   [화산]  [산악 MTB 숲]
     ↘        ↓
       [언덕 주택가 / 와이너리]
            ↓
   [꼬인 도심 다운힐] ── [공사장]
            ↓
   [평지 도심 / 스폰]
            ↓
   [항구 / 해변 / 부두]
```

- 위에서 아래로 자연스럽게 이어지는 구조.
- 오픈월드 곳곳에 숨은 점프대와 지름길.
- **StreamingEnabled 필수** (플레이어 근처만 불러오는 기능). 처음부터 켜고 개발한다. 스크립트는 "멀리 있는 물체가 아직 로드 안 됐을 수 있음"을 항상 고려한다.

### 4-2. 레이스 코스 목록 (초안)
**긴 맵: 출발과 도착이 다름, 1바퀴**
| 코스 | 구간 | 특징 |
|---|---|---|
| 정상에서 바다까지 | 설산 → MTB → 도심 → 항구 | 최장 코스 |
| 눈사태 탈출 | 설산 정상 → 중턱 | 뒤에서 눈사태 연출 |
| MTB 데스 트레일 | 숲 하강 | 나무 사이 좁은 길, 바위, 통나무 다리 |
| 도심 다운힐 | 언덕 → 도심 | 계단, 골목, 지붕 점프, 시장 천막 |
| 화산 탈출 | 분화구 → 산기슭 | 떨어지는 돌, 무너지는 용암 다리 |
| 부두 질주 | 도심 → 항구 끝 | 컨테이너 사이, 배로 점프해서 골인 |

**둥근 맵: 순환형, 길이에 따라 2~3바퀴**
| 코스 | 바퀴 | 특징 |
|---|---|---|
| 분화구 링 | 3 | 분화구 안 나선형, 안쪽은 용암 가까운 지름길 |
| 주차장 나선탑 | 3 | 빌딩 주차장 오르내리기 |
| 도심 블록 서킷 | 3 | 시내 블록, 육교, 터널 |
| 빙판 호수 | 2 | 얼음 위 드리프트 |
| 공사장 서킷 | 2 | 크레인 아래, 철골 위 |
| 와이너리 언덕 | 2 | 포도밭 오르막 내리막 |

**웃음 특화 코스 (가끔 투표에 섞기)**
- 지붕 위 레이스, 수직 낙하, 해변 모래밭

> 바퀴 수는 코스 데이터에 각자 설정한다 (코드에 고정하지 않음).

### 4-3. 점프대 배치 원칙
| 종류 | 위치 | 역할 |
|---|---|---|
| 지름길 점프대 | 커브 바깥, 건물 사이 | 성공하면 시간 단축, 실패하면 낙하 데미지 |
| 연결 점프대 | 구역 경계 | 구역끼리 자연스럽게 연결 |
| 놀이 점프대 | 광장, 해변, 공사장 | 오픈월드에서 노는 용도 |
| 함정 점프대 | 웃음 특화 코스 | 너무 세게 날려서 엉뚱한 곳 착지 |

- 레이스 코스는 착지 지점이 눈에 보이게 (운이 아니라 실력).
- 일반 착지는 데미지 적게, 지름길 실패는 크게.
- 출발 직후엔 점프대 두지 않기.
- 코스 후반에 큰 점프대 하나 (역전 기회).

## 5. 레이스 시스템

- **5분마다** 레이스 투표가 뜬다.
- 투표에는 **랜덤 코스 3개**.
- 플레이어는 **참여 또는 거부** 선택 가능.
- **최대 8명.**
- 참여하면 지금 타고 있는 차(+튜닝, +동승자)로 출발선에 이동.
- **출발 후 일정 시간 고스트 모드** (레이서끼리 충돌 없음, 반투명). 약 5초 제안, 끝나기 직전 깜빡임.
- 체크포인트 방식. 폭발하면 마지막 체크포인트에서 부활 + 2~3초 고스트.
- 동승한 채로 참여 가능, 도중 하차 불가.
- **튜닝 차이에 따른 매칭 보정 없음** (오래 키운 사람이 강한 것을 의도함).

### 코스별 기록 탭
- 메뉴에 기록 탭. 코스를 고르면 그 코스 최고 기록 순위가 보임.
- 내 최고 기록, 서버 순위, 전체 순위.
- 기록 옆에 사용한 차 (+ 튜닝 정보 공개 여부는 미정).
- 전체 순위 저장은 OrderedDataStore 같은 순위용 저장소 사용 검토.

## 6. 경제 (돈)

- **돌아다니기만 해도 돈이 조금씩 들어옴.** 속도가 빠를수록 많이.
- **스타일 보너스**: 아슬아슬하게 피하기, 깔끔한 드리프트, 공중재비 후 완벽 착지.
- 레이스 보상 (구체적 수치 미정).
- 돈으로 차 구매, 튜닝 레벨업, 타이어 해금.
- 모든 수치(벌이 속도, 가격, 튜닝 비용 곡선)는 **한 곳의 설정 데이터**에서 조절 가능하게.

## 7. ❓ 미정 / Claude Code가 질문해야 할 것

구현하다 아래에 닿으면 **멈추고 개발자에게 질문**한다.

### 규칙 관련
1. **레이스 중 오픈월드 플레이어 처리**: 레이스 코스가 오픈월드 안에 있는데, 레이스 안 하는 사람이 코스 위를 달리고 있으면? (레이서와 충돌 끄기 / 코스 막기 / 그냥 두기)
2. **오픈월드에서 폭발한 후**: 어디서 부활? 차는 바로 다시 나오는지, 쿨타임이 있는지?
3. **레이스 투표가 떴을 때 이미 진행 중인 레이스가 있으면?** (5분 주기와 레이스 길이가 겹치는 경우)
4. **8명 넘게 참여하면?** 선착순 / 랜덤 / 다음 레이스 대기
5. **관광버스(8인승)로 레이스 참여 시** 동승자도 레이스 인원 8명에 포함되는지
6. 동승자가 **차 주인이 아닌 사람**일 때 탑승 허용 규칙 (아무나 / 친구만 / 운전자가 허락) 및 **운전자가 동승자 내쫓기** 기능 여부
7. 레이스 순위 기준 확인: 먼저 들어온 순서 (긴 맵, 둥근 맵 모두)
8. 기록 탭: 솔로 / 동승 기록을 나눌지, 차 종류별로 나눌지

### 수치 관련 (임시값 가능, 표시해 두고 나중에 확인)
9. 각 차의 가격과 기본 능력치, 좌석 수
10. 튜닝 최대 레벨과 레벨별 비용 곡선
11. HP 수치, 충격 데미지 계산 기준, 회복 속도
12. 동승자 때리기 쿨타임과 핸들 꺾임 세기
13. 고스트 시간 (출발 5초 제안, 부활 2~3초)
14. 돈 버는 속도, 스타일 보너스 금액, 레이스 보상

### 플랫폼 관련
15. **모바일 / 게임패드 조작**: 지금은 PC 키만 정해짐. 모바일 버튼 배치를 어떻게 할지 (로블록스 유저 상당수가 모바일)
16. 아케이드 보정 정도 (뒤집힘 자동 복구 여부 등)

### 나중에 정할 것
17. 수익 모델 (로벅스 판매 품목)
18. 게임 이름

## 8. 확장성 설계 가이드

나중에 차, 코스, 튜닝, 타이어, 맵 구역이 계속 늘어난다. 아래 원칙을 지킨다.

### 8-1. 데이터 주도 설계
게임 내용을 **설정 모듈(ModuleScript)**에 데이터로 정의하고, 코드는 그 데이터를 읽어서 동작한다.

예시 구조 (최종 구조는 Claude Code가 제안하고 개발자 확인 후 진행):
```
ReplicatedStorage
  Config
    VehicleConfig      -- 차 목록: id, 표시 이름, 가격, 기본 능력치, 좌석 수, 모델 경로, 특수 효과 id
    TuningConfig       -- 튜닝 항목: id, 방식(레벨/슬라이더/종류), 최대 레벨, 비용 곡선, 어떤 능력치에 영향
    TireConfig         -- 타이어 종류: id, 이름, 접지력 등
    CourseConfig       -- 코스: id, 이름, 타입(긴 맵/둥근 맵), 바퀴 수, 체크포인트 폴더 경로, 출발 위치
    EconomyConfig      -- 돈 관련 수치
    GameplayConfig     -- HP, 고스트 시간, 레이스 주기(5분), 최대 인원(8) 등
    InputConfig        -- 키 설정
  VehicleModels        -- 차 모델 (VehicleConfig의 id와 이름 일치)
```

- **새 차 추가** = VehicleConfig에 항목 추가 + VehicleModels에 모델 넣기. 끝.
- **새 코스 추가** = CourseConfig에 항목 추가 + 오픈월드에 체크포인트 폴더 배치. 끝.
- **새 튜닝 항목 추가** = TuningConfig에 항목 추가 + 해당 능력치 계산에 반영.
- 차마다 특별한 효과(주전자 증기, 냉장고 음식 폭발, 자판기 캔 등)는 **효과 모듈을 id로 연결**하는 방식으로, 차 공통 코드에 if문으로 넣지 않는다.

### 8-2. 능력치 계산 한 곳에서
- "최종 능력치 = 차 기본값 + 튜닝 보정" 계산을 **한 모듈**에서만 한다.
- 나중에 이벤트 보너스, 스킨 효과 등이 추가돼도 여기만 고치면 되게.

### 8-3. 저장 데이터
- 플레이어 데이터: 돈, 보유 차, 차별 튜닝 상태, 타이어 해금, 코스별 최고 기록 등.
- **데이터 버전 번호**를 넣어서 나중에 구조가 바뀌어도 옛날 데이터를 변환할 수 있게.
- 새 항목이 생겨도 기존 데이터가 깨지지 않게 기본값 채우기.

### 8-4. 모델 규칙
- 차 모델 구조(바퀴 파트 이름, 좌석 위치, 헤드라이트 파트, 데칼 위치 등)를 **규칙으로 정하고 문서화**한다. 규칙을 정한 뒤 개발자에게 알려 줘서, 개발자가 새 차를 만들 때 따라 할 수 있게.

## 9. 기술 주의사항

- **네트워크 소유권**: 차는 운전자에게 소유권을 줘야 렉 없이 부드럽다. 대신 클라이언트가 위치를 계산하므로 **서버에서 속도·순간이동·체크포인트 건너뛰기 검사** 필요.
- **돈, 튜닝, 구매, 기록은 반드시 서버에서 처리.** 클라이언트가 보내는 값을 그대로 믿지 않는다.
- **레이스 기록**은 서버가 체크포인트 통과를 확인한 것만 인정.
- **StreamingEnabled** 처음부터 켜기.
- **고스트 모드**는 충돌 그룹(Collision Group)으로 구현 검토.
- **폭발과 래그돌**은 효과가 크니 동시에 여러 개 터져도 성능 괜찮은지 확인 (특히 모바일).
- 큰 맵이라 파트 수, 그림자, 효과 수 관리 필요.

## 10. 개발 순서 제안

한 번에 다 만들지 말고 단계별로. (순서는 Claude Code가 조정 제안 가능)

1. **차량 기본**: 차 1~2대, 물리 주행 + 아케이드 보정, 조작(W/S/A/D, Space 드리프트, Shift 부스터, F, L, C), 동승, 카메라
2. **HP / 폭발 / 래그돌 / 자동 회복**
3. **데이터 구조**: Config 모듈들, 능력치 계산 모듈, 저장 시스템
4. **튜닝 시스템 + UI**, 차 구매
5. **돈**: 주행 수입, 스타일 보너스
6. **레이스 시스템**: 투표, 참여/거부, 체크포인트, 바퀴 수, 고스트, 부활, 순위, 보상
7. **기록 탭**
8. **동승자 머리 때리기**
9. **맵**: 평지 도심 + 산 구역부터 → 설산 → 화산 순서로 확장
10. **차 대량 추가** (데이터 구조가 잡힌 후)
